01 / Первые пять минут

  1. Откройте каталог и нажмите «Обновить объявления». В Mock-режиме ключ не нужен: приложение сохраняет учебную выборку.
  2. Выберите «Потенциально выгодные». Это предложения со скидкой от 10%, положительной прибылью после расходов и риском до 40 из 100.
  3. Уточните марку, модель, бюджет и пробег. После выбора марки список моделей сужается. Нажмите «Показать автомобили». Убрать один фильтр можно крестиком над карточками.
  4. Откройте автомобиль. Сравните его цену с аналогами, прочитайте описание, проверьте найденные фразы и недостающие сведения.
  5. Введите предполагаемый ремонт и остальные расходы. Предпросмотр прибыли меняется сразу; «Пересчитать и сохранить» записывает расходы в БД и обновляет балл.
  6. Если вариант интересен, перейдите к оригиналу объявления и договоритесь об осмотре. У учебных объявлений оригинала нет.

Сохраните адрес страницы результатов: фильтры и сортировка записаны в URL. Этот адрес откроет ту же выборку на том же запущенном приложении.

02 / Откуда берётся оценка

Приложение ищет похожие активные автомобили: та же марка и модель, близкий год и пробег, похожий двигатель, одинаковые топливо и коробка. Сначала пробует ваш регион. Сама оцениваемая машина в своих аналогах не участвует.

Из выборки исключаются явные ценовые выбросы и объявления с серьёзными признаками проблем. Рыночная оценка — медиана оставшихся цен: центральное значение, которое меньше зависит от одного очень дорогого объявления.

Пример: 13 000 − 10 000 − 700 − 400 = 1 900 $

13 000 $ — оценка рынка; 10 000 $ — продавец; 700 $ — ремонт; 400 $ — оформление, доставка и другие расходы. Потенциальная прибыль — 1 900 $, если удастся продать по оценке рынка.

Это учебный пример, не прогноз дохода. Оценка использует цены предложений, а не реальные цены состоявшихся сделок.

Что означает балл

Итоговый балл 0–100 помогает расставить приоритеты для просмотра. Он учитывает скидку, прибыль после расходов, количество аналогов, пробег, возраст наблюдения, условную ликвидность и признаки риска. В карточке виден вклад каждого компонента. Балл 80 не означает вероятность прибыли 80%.

Почему бывает «Недостаточно данных»

По умолчанию нужны минимум пять аналогов после очистки. Если их мало или отсутствуют ключевые характеристики, приложение не придумывает рыночную цену. Расширьте импортируемую выборку; снижение минимума делает оценку менее устойчивой.

Почему риск не равен диагнозу

Фразы «после ДТП», «не растаможен», «требует ремонта» — повод задавать вопросы. Правила могут ошибаться в контексте и отрицаниях. Отсутствие стоп-фраз и наличие VIN не означают успешную юридическую проверку.

03 / Данные и фотографии

Mock — демонстрация с вымышленными ценами и описаниями. Фото взяты из Wikimedia Commons отдельно для каждой модели. Снимки одного модельного ряда могут повторяться: это примеры модели, не уникальные объявления продавцов.

AUTO.RIA — реальные карточки через официальный API. Сейчас сохраняется главная фотография, URL которой вернул API. Демо-фото никогда не подставляются в реальные объявления.

При первом импорте создаётся запись цены; при изменении — следующая. История начинается с первого наблюдения приложением. Для проверки графика в демо выполните:

docker compose exec app python -m scripts.seed --with-history

Обычный повторный импорт не создаёт дубли. Ваши ручные расходы сохраняются. Не найденное объявление снимается только после полного обхода той же выборки и заданного срока отсутствия. Ограниченная первая страница поиска не доказывает, что автомобиль продан.

04 / Подключение AUTO.RIA

  1. Создайте аккаунт на портале разработчиков AUTO.RIA и получите ключ.
  2. В папке проекта скопируйте .env.example в .env. Если файл уже существует, отредактируйте его, не заменяя прежние настройки.
  3. Заполните настройки ниже. Настоящий ключ указывайте только локально в .env.
LISTING_PROVIDER=autoria
AUTORIA_API_KEY=ваш_ключ
IMPORT_INTERVAL_MINUTES=1440
AUTORIA_MAX_PAGES=1
AUTORIA_PAGE_SIZE=20

В AUTORIA_SEARCH_PARAMS задайте JSON с документированными ID и параметрами поиска. Фильтры каталога работают по уже загруженной базе, а не меняют этот запрос.

docker compose up -d --force-recreate app
docker compose logs -f app

По умолчанию поиск и 20 карточек требуют до 21 запроса за проход без повторов. Квота общая для API-ключа. Повторный реальный импорт соблюдает настроенный интервал. При ошибке 429 дождитесь восстановления квоты; при 401/403 проверьте ключ и доступ. Официальная документация ↗

05 / Сохранить проект в GitHub

Git хранит историю изменений в вашем проекте. GitHub хранит удалённую копию этой истории. Docker запускает приложение. Загрузка файлов на GitHub сама по себе не запускает FastAPI и PostgreSQL.

Скачать подробную инструкцию GitHub → — установка, авторизация, первый репозиторий, push, ветки, автоматические тесты, перенос на другой компьютер и разбор ошибок.

Самый понятный путь

  1. Установите GitHub Desktop с официального сайта и войдите в свой аккаунт.
  2. Создайте локальный репозиторий в уже существующей папке проекта. Для этого можно выполнить git init -b main в терминале из папки PEREKUP, затем выбрать её через File → Add local repository в Desktop.
  3. Проверьте список изменений: там должны быть исходники и .env.example, но не .env, .venv или база данных.
  4. Создайте первый commit с понятным названием.
  5. Нажмите Publish repository, оставьте Keep this code private включённым и опубликуйте репозиторий.
  6. На странице репозитория откройте Actions: подготовленный workflow запускает тесты и проверяет Docker-сборку. Зелёная отметка появится только после успешного выполнения.

Что менять каждый день

Изменили код → проверили приложение → посмотрели diff → создали commit → отправили Push. Для заметного изменения создавайте отдельную ветку и Pull Request: так проще понять и проверить изменения до их объединения.

API-ключ не нужен для автоматических тестов: они используют MockProvider и подменённые HTTP-ответы. Не добавляйте реальный ключ в workflow.

06 / Как показать приложение другим

GitHub Pages здесь не подходит: он публикует статические файлы, а этому приложению нужны работающий Python-сервер, PostgreSQL и планировщик.

Для личного удалённого использования можно запустить Docker Compose на своём сервере и подключаться через SSH-туннель. Полная инструкция приведена в скачиваемом руководстве. База остаётся на сервере, а порт приложения не открывается всем в интернете.

Для публичной версии потребуются отдельные настройки HTTPS, доступа, пароля БД, резервного копирования и секретов. Текущий Compose рассчитан на локальное использование одного человека. Публикация репозитория и публикация работающего сервиса — два разных действия.

07 / Частые вопросы

Почему я не вижу новых фото?

Нажмите «Обновить объявления», затем обновите страницу. Старые записи в базе получают новые URL при импорте. Если вы запускаете Docker после изменения исходников, сначала выполните docker compose up --build -d.

Почему цена на сайте отличается от оценки?

Оценка — медиана похожих предложений из загруженной выборки, а не подтверждённая стоимость конкретной машины. Комплектация, состояние, срочность, регион и неполные данные могут менять цену.

Куда пропадут данные после остановки Docker?

Обычная команда docker compose down сохраняет именованный том PostgreSQL. down -v удалит этот том вместе с базой. GitHub не хранит резервную копию ваших объявлений.

Что делать, если порт 8000 занят?

Остановите предыдущий локальный сервер через Ctrl+C в его терминале или свой ранее запущенный Compose. Не завершайте неизвестный процесс наугад. В руководстве есть команды для просмотра владельца порта.

Мне нужен OpenAI API-ключ?

Нет. Оценка и анализ описаний работают локально по формулам и словарю. Данные во внешний ИИ не отправляются.
