# ПЕРЕКУП

**Начать здесь:** [как пользоваться приложением](docs/USER_GUIDE.md) · [GitHub: инструкция с нуля](docs/GITHUB.md) · [AUTO.RIA](docs/AUTORIA.md). В приложении есть раздел [«Как пользоваться»](http://localhost:8000/guide).

Рабочий MVP для предварительного отбора автомобилей на украинском рынке: импорт объявлений, подбор аналогов, медианная оценка рынка, расходы, риски и объяснимый балл. Интерфейс на русском, без React. Python 3.12, FastAPI, PostgreSQL, SQLAlchemy 2, Alembic, APScheduler, Jinja2 и обычный JavaScript.

**Оценка приблизительная, прибыль не гарантируется. Каждый автомобиль нужно проверять лично, технически и юридически.**

## Быстрый запуск

Нужны Docker Desktop с запущенным движком и Docker Compose **2.24 или новее** (используется необязательный `.env`). Откройте терминал в каталоге проекта:

```bash
cd /Users/aleksandrlymar/Desktop/PEREKUP
docker compose up --build
```

Откройте [http://localhost:8000](http://localhost:8000). Swagger: [http://localhost:8000/docs](http://localhost:8000/docs). Проверка здоровья: [http://localhost:8000/health](http://localhost:8000/health).

Команда поднимает PostgreSQL, ждёт его готовности, применяет миграции, запускает один процесс приложения и автоматически импортирует 41 тестовое объявление. `.env` и ключ API для Mock-режима необязательны. Первый запуск требует интернета для загрузки образов и Python-зависимостей. Первый импорт происходит в фоне: страница подхватывает результат автоматически.

### Установка Docker

На этом Mac нужен [Docker Desktop для macOS](https://docs.docker.com/desktop/setup/install/mac-install/): выберите установщик для Apple silicon или Intel, перенесите приложение в Applications и запустите. Завершите первоначальную настройку и дождитесь готовности движка. Для других компьютеров есть [инструкции Docker Desktop](https://docs.docker.com/desktop/).

```bash
docker --version
docker compose version
docker info
```

Если команда не найдена, завершите установку CLI в настройках Docker и переоткройте терминал. Если движок недоступен, запустите Docker Desktop. Compose старше 2.24 обновите вместе с Docker Desktop: [описание необязательных env-файлов](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/).

cp .env.example .env

После изменения настроек:

```bash
docker compose up -d --force-recreate app
```

Расходы из `.env` применяются к новым оценкам. Введённые на странице автомобиля значения сохраняются при следующих импортах и имеют приоритет.

Приложение предназначено для локального использования: опубликован только порт `127.0.0.1:8000`, порт БД не опубликован. В локальной сети Compose PostgreSQL использует `trust` без пароля, чтобы демо запускалось одной командой без секретов. Для внешнего сервера потребуется настроить пароль БД, доступ и аутентификацию приложения; этот Compose не является конфигурацией публичного сервиса. Если указываете собственную БД в DATABASE_URL, её миграции будут применены при старте — используйте выделенную базу этого проекта.

## Mock-режим и история цены

Тестовая выборка содержит Volkswagen Golf, Skoda Octavia, Renault Megane, Toyota Camry и редкую Mazda MX-5. Есть группы аналогов, дешёвые предложения, повреждённые машины, ценовые выбросы и недостаток данных. Цены и описания вымышлены. Фотографии подобраны отдельно по моделям из Wikimedia Commons. Это примеры моделей, не конкретные машины продавцов; внутри одной модели они могут повторяться. [Авторы и лицензии](docs/PHOTO_CREDITS.md).

Ручной импорт доступен кнопкой «Обновить объявления». Для заполнения БД командой:

```bash
docker compose exec app python -m scripts.seed

# Дополнительно создаёт изменение цены у четырёх объявлений
docker compose exec app python -m scripts.seed --with-history
```

История содержит реальные времена тестовых импортов, а не выдуманные даты. Обычный повторный импорт неизменённых цен не добавляет историю. `--with-history` сначала импортирует вариант с четырьмя снижениями на 300 $, затем базовые цены; команда не обращается к AUTO.RIA. При первом старте у каждой машины одна исходная запись истории.

Проверьте сценарий: отфильтруйте марку, откройте дешёвую машину, измените ремонт и дополнительные расходы, сохраните. Прибыль и балл обновятся; после нового импорта ваши расходы сохранятся. Для MX-5 отображается «Недостаточно данных».

## Подключение AUTO.RIA

1. Получите API-ключ на [официальном портале](https://developers.ria.com/).
2. Укажите в `.env`:

```dotenv
LISTING_PROVIDER=autoria
AUTORIA_API_KEY=ваш_ключ
IMPORT_INTERVAL_MINUTES=1440
AUTORIA_MAX_PAGES=1
AUTORIA_PAGE_SIZE=20
```

3. В `AUTORIA_SEARCH_PARAMS` задайте узкую выборку через официальные ID марки/модели и параметры из документации. Значение должно быть JSON-объектом. Не передавайте туда `api_key`, `page`, `countpage`: они задаются отдельно.
4. Пересоздайте контейнер приложения и следите за статусом импорта.

По умолчанию поиск ограничен параметрами из `.env.example`. Небольшая выборка может не дать пяти подходящих аналогов. UI-фильтры работают **по локально импортированным данным** и сами не отправляют запросов в AUTO.RIA. При смене провайдера интерфейс переключает источник; Mock-объявления никогда не участвуют в оценке реальных.

Адреса API и поля проверены по текущей официальной документации. Подробнее: [docs/AUTORIA.md](docs/AUTORIA.md). Бесплатная квота ограничена, поэтому реальный ручной импорт также соблюдает настроенный интервал, минимум час. При 429 импорт останавливается; при 401/403 сообщается о ключе/доступе; частично изменённые данные не сохраняются. Журналы не записывают ключ и полные HTTP-исключения.

Платный сервис статистики по периодам вынесен в `app/services/autoria_statistics.py`, но **не вызывается автоматически**. Для него нужны доступ к платному методу и `user_id`. MVP использует локальную медиану; внешний ИИ не подключён. RST содержит только явно неподключённую заготовку, без парсинга и обхода защиты.

## Как работает оценка

Логика находится в `app/services/scoring.py`.

1. Выбираются активные объявления того же источника, марки и модели, кроме самого оцениваемого автомобиля. При наличии поколения оно должно совпадать.
2. Год отличается не больше чем на 2; топливо и коробка совпадают; объём двигателя отличается не больше чем на 0,31 л; пробег — не больше чем на максимум из 40 000 км и 30% пробега целевого автомобиля. Пропущенные ключевые параметры не считаются совпадением.
3. Из аналогов исключаются объявления со средними/высокими признаками повреждений и документальных проблем. Это также может ошибаться из-за контекста описания.
4. Сначала пробуется тот же регион. Если после очистки аналогов мало, используется общая выборка.
5. Выбросом считается отклонение цены от медианы больше `max(3 × MAD, 20% медианы)`. MAD — медиана абсолютных отклонений. Повторно проверяется минимальное количество аналогов.
6. При недостатке данных рыночная цена, прибыль, процент скидки и итоговый балл равны `null`, а интерфейс объясняет причину.

```text
потенциальная прибыль = медиана аналогов − цена продавца − ремонт − дополнительные расходы
скидка, % = (медиана − цена продавца) / медиана × 100
```

Состав итогового балла:

| Компонент | Баллы |
| --- | --- |
| Скидка | min(30, max(0, скидка %) × 1,5) |
| Доходность после расходов | min(25, max(0, прибыль / цена) × 250) |
| Размер выборки после очистки | min(15, количество аналогов × 1,5) |
| Условная ликвидность | min(100, количество подходящих предложений × 8) × 0,1 |
| Пробег | max(0, 10 − штраф за пробег × 0,5) |
| Возраст наблюдения | max(0, 10 − дни с первого наблюдения / 3) |
| Риск | −0,5 × риск |

Сумма ограничивается диапазоном 0–100. Понятие ликвидности здесь условное: предложение на рынке не является достоверным измерением спроса или скорости продажи.

Риск ограничен 0–100: сумма баллов найденных фраз + 4 за каждое отсутствующее существенное поле + штраф за пробег + 2 за каждую недостающую фотографию до пяти. Пробег: 12 баллов при неизвестном значении, иначе от 0 до 20 за превышение 150 000 км (один балл на 10 000 км). Все составляющие показаны в карточке. Высокая привлекательность не заменяет проверку автомобиля.

Словарь фраз: `app/services/description.py`. Класс `DescriptionAnalyzer` позволяет заменить правила другим анализатором. Правила понимают русские и украинские фразы, различают степени риска и некоторые простые отрицания. Совпадения — сигналы для проверки, не доказательства.

## Импорт и база

Таблицы: `listings`, `listing_photos`, `price_history`, `deal_scores`, а также `import_runs` для времени и результата обновлений. Пара `(source, external_id)` уникальна на уровне БД. `deal_scores` хранит последнюю оценку на объявление; цены хранятся отдельной историей. Денежные поля — Decimal/Numeric с двумя знаками.

Импорт выполняется атомарно. Внутри одного процесса используется блокировка; в PostgreSQL дополнительно применяется транзакционная advisory lock. Ручной пересчёт использует ту же блокировку. Отдельный импорт в фоне не блокирует чтение каталога. Одновременный импорт/пересчёт получает 409. APScheduler запускается с одним экземпляром задачи и `coalesce`; используется **один worker Uvicorn**.

Автоматическое снятие по отсутствию работает только после успешного полного обхода той же выборки и истечения INACTIVE_AFTER_DAYS. При ограниченном числе страниц отсутствие не доказывает снятие: запись остаётся активной, а интерфейс показывает предупреждение. Явные статусы API учитываются сразу. Снятие в БД не удаляет историю.

## Локальный просмотр без Docker

Основной вариант использует PostgreSQL. Для разработки или просмотра на компьютере без Docker поддержана SQLite:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=sqlite:///./dev.db
export LISTING_PROVIDER=mock
alembic upgrade head
python -m scripts.seed --with-history
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

SQLite не заменяет проверку на PostgreSQL перед использованием реальных данных. Для перехода к Docker остановите локальный сервер сочетанием Ctrl+C и уберите экспорт `DATABASE_URL` из текущего терминала (`unset DATABASE_URL`), чтобы Compose использовал свою БД. Данные SQLite автоматически не переносятся в PostgreSQL.

## Ограничения MVP

- Локальный инструмент для одного пользователя, без авторизации, оплаты и публичного размещения.
- Оценка строится по ценам предложений, а не подтверждённых продаж. Выборка может быть неполной, устаревшей или смещённой; торг и фактическая цена сделки неизвестны.
- Ликвидность — эвристика. Ремонт и расходы задаются вручную; налоги, переоформление и перевозка автоматически не рассчитываются.
- Распознавание описаний ограничено словарём. Анализ фотографий, юридические проверки, LLM и ML отсутствуют.
- В AUTO.RIA сейчас импортируется главное фото; видимые поля могут зависеть от объявления и доступа ключа. Известные пробелы описаны в `docs/AUTORIA.md`.
- Для ограниченной выборки снятие по отсутствию отключено. Старые строки других поисковых параметров сохраняются.
- Балл обновляется при импорте/ручном пересчёте, а не каждую минуту. Возраст — время наблюдения приложением, не дата публикации на площадке.
- Медиана считает похожие объявления в памяти внутри групп марки/модели. Это подходит для небольшой локальной выборки; массовый сбор потребует отдельной оптимизации и согласованной квоты.
- Подключение AUTO.RIA написано по документации и проверено контрактными тестами. Запрос с настоящим ключом ещё нужно проверить на вашем аккаунте.

## Что проверено при создании

На этом компьютере выполнены тесты на Python 3.12 и SQLite, применена миграция, проверено отсутствие расхождения моделей/схемы, сгенерирован SQL для PostgreSQL, выполнена синтаксическая проверка JavaScript и запущен HTTP-сервер. Docker здесь не установлен, поэтому фактический `docker compose up --build` и тесты на живом PostgreSQL ещё не выполнялись. Это ограничение окружения, а не утверждение об успешном контейнерном тесте.
